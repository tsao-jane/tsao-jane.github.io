Case study · Product data

From about a week to a day per vendor update

The storefront carries a catalog of 5,500+ visible products, synced through NetSuite. Keeping it current used to mean a week of manual entry per vendor update. I built an AI-assisted import pipeline for five vendor lines that crawls and formats the data, and leaves the judgement calls to me.

“a week to a day” is my own estimate

  • 5 vendor lines
  • 5,500+ visible products
  • ~1 week → 1 day per update (my estimate)
  • Packaged as reusable Claude Skills

The pipeline

crawl, format, check, import

  1. AI-assistedCrawl the vendor siteProduct pages, specs, images and datasheet links are collected per vendor.
  2. AI-assistedFormat to the vendor’s CSVEach vendor has its own column layout and spec rules; the data is shaped to fit it.
  3. MeCheckSpec parsing rules, dead-link checks, and the call on whether a change is a revision or a new product.
  4. MeImportThe checked file goes into the product CMS and syncs to the storefront.

Around the pipeline sit 15 small single-purpose Python scripts: link checks, image fetching, spec fixes, and a safe spreadsheet rebuild. One Cincoze run in August 2026 covered 107 products.

What AI does

  • Collects product data from vendor pages instead of someone retyping it.
  • Shapes it into each vendor’s CSV layout.
  • Drafts the repetitive parts so I spend my time on exceptions.

What I still check by hand

  • Spec parsing rules: a wrong unit or a mangled SKU is worse than a missing one.
  • Dead links and missing images before anything is imported.
  • Revision versus rename: whether a vendor change is the same product or a new one.
  • Anything that touches price. I prepare the NetSuite import files that set up new vendor items and update purchase and list prices from vendor price lists.

So the method survives me

I packaged the vendor price-update and product-knowledge methods as reusable Claude Skills, so the next person can run the same steps with the same checks.
